# 建材商户平台

面向建材市场的三端平台：平台管理后台（管商户）+ 商户端（管门店与产品）+ 微信小程序（找产品/调货）。

核心业务目标：商户入驻（365 元 / 年）→ 发布产品 → 小程序展示 → 同行调货、跨区域价格对比、厂家找渠道。

---

## 三、启动步骤

### 1. 选择数据库模式（二选一）

数据库结构由 **Flyway** 统一管理，脚本位于 `server/src/main/resources/db/migration`，MySQL 与 H2 共用同一套迁移，后端启动时自动建表并写入演示数据，无需手工执行 SQL。

**方式 A：H2 内存库（备用，开箱即用）**

不需要安装任何数据库，把 `application.yml` 的 `spring.profiles.active` 改回 `h2` 即可。
数据保存在内存中，**重启服务后会恢复为初始演示数据**，适合临时演示。

**方式 B：MySQL 8（当前启用 ✅）**

本机已安装免安装版 MySQL 8.0.28（位于 `D:\mysql-8.0.28-winx64`，账号 root/root，库名 jiancai），
`application.yml` 已切换为 `active: mysql`，数据持久化不丢失。

数据库启动方式（电脑重启后需手动执行）：

```
D:\mysql-8.0.28-winx64\bin\mysqld.exe --defaults-file=D:\mysql-8.0.28-winx64\my.ini
```

重置数据库（会清空重建，仅在需要恢复演示数据时使用）：删库后重启后端，Flyway 会自动重新执行全部迁移：

```
D:\mysql-8.0.28-winx64\bin\mysql.exe -uroot -proot -e "DROP DATABASE IF EXISTS jiancai;"
```

> 已有库首次接入 Flyway 时会以 V2 建立基线、跳过历史脚本，不会覆盖现有数据；后续新增脚本从 `V3__` 起按版本号自动执行。
> 修改表结构请新增迁移脚本，不要直接改库或改历史脚本（Flyway 会校验校验和）。

### 2. 配置图片上传

默认保存到本地：

```yaml
jiancai:
  upload:
    path: D:/jiancai-upload/   # 图片保存目录，需有写权限
```

生产环境建议使用**阿里云 OSS**。凭据不要写进仓库，放到工作目录下的 `server/config/application.yml`（已加入 `.gitignore`，Spring Boot 会自动加载），或用同名环境变量注入：

```yaml
jiancai:
  oss:
    endpoint: oss-cn-beijing.aliyuncs.com   # 或 OSS_ENDPOINT
    bucket: cailutong                      # 或 OSS_BUCKET
    access-key-id: xxxx                    # 或 OSS_ACCESS_KEY_ID
    access-key-secret: xxxx                # 或 OSS_ACCESS_KEY_SECRET
    public-domain:                         # 可选，CDN/自定义域名；留空用 https://{bucket}.{endpoint}
    dir-prefix: jiancai                    # 对象前缀，最终形如 jiancai/2026/11/uuid.jpg
```

- 未配置 `access-key-id`/`access-key-secret` 时自动回退本地磁盘，无需改代码。
- 图片需公开访问，请把 Bucket 读写权限设为**公共读**（若提示被"阻止公共访问"拦截，需先行关闭）。
- `server/config/application.yml` 依赖工作目录为 `server/`，请在 `server` 目录下启动后端。

| 前缀 | 说明 | 鉴权 |
|---|---|---|
| `/api/auth/**` | 登录、商户入驻申请 | 否 |
| `/api/mp/**` | 小程序：首页聚合、品类、产品列表/详情、**商户列表/市场/商户主页**、**附近距离排序**、**价格排序**、**比价搜索**、**同款比价**、**微信登录（code 换 openid）**、**用户昵称/头像**、商户入驻、浏览/转发/**电话联系**上报、浏览记录、**我的询价/报价查看**、**产品与商户收藏** | 否 |
| `/api/admin/**` | 平台端：商户管理（含经营画像）、**小程序用户管理（详情/备注/导出）**、**全平台询价管理**、产品审核、品类、轮播/广告、数据总览与**趋势统计** | 管理员 |
| `/api/merchant/**` | 商户端：门店信息、产品发布/上下架、数据看板、**询价报价与跟进**、**站内消息（会话/回复）** | 商户 |

## 五、业务流转

```
小程序"免费入驻"提交资料（pages/apply → /api/auth/register）
      ↓ 状态=待审核
平台端商户管理 → 审核通过 → 自动开通商户账号（手机号/123456）
      ↓
商户登录商户端 → 维护门店 → 发布产品（状态=待审核）
      ↓
平台端产品管理 → 审核通过 → 在售
      ↓
小程序展示：首页 / 商户列表 / 产品列表 / 详情页同款比价
      ↓
用户浏览、转发、电话询价（统计回流到商户端"被浏览/被转发"）
      ↓
用户提交询价（数量/期望到货/联系方式）→ 商户端报价（单价/总价/有效期）
      ↓
小程序「我的-我的询价」查看报价 → 电话或到店成交
      ↓
另一条链路：商品详情/商户主页「在线咨询」→ 站内会话收发文字、图片、商品卡片
      ↓
商户在小程序「商家中心-我的消息」回复 → 用户端实时收到（WebSocket），离线时靠订阅消息提醒
```

## 六、核心能力说明

**小程序价格对比**（同行调货、跨商户比价的核心）：

- **列表页价格排序**：`GET /api/mp/products?sort=price_asc`，同款产品按价格从低到高排列
- **详情页同款比价**：`GET /api/mp/product/compare?id=`，匹配优先级「同名 → 同品类+品牌+类型 → 同品类」，展示其他商户报价并可一键电话询价
- **比价搜索**：`GET /api/mp/price-compare?keyword=`，输入产品名或品牌，返回各家按价格升序的报价

**品类管理（最多三级）**：平台端「品类管理」为可折叠树，支持在一级/二级品类下新增子类，三级品类不可再加子类；按一级/二级品类筛选产品时会一并包含其下所有子类的产品。

**商户入驻（当前免费）**：小程序「我的」→ 商户入驻 → 填写资料（含门头照上传）→ 平台端商户管理审核 → 通过后自动开通账号。

**行为记录（浏览 / 转发 / 电话联系）**：

- 小程序三处拨号（产品页「电话联系档口」、比价列表「电话询价」、商户主页拨号）均上报 `POST /api/mp/call`
- 每次浏览、转发、拨号写入 `view_record` / `forward_record` / `call_record`，并同步累加产品与商户的 `views` / `forwards` / `calls` 计数
- 商户端「数据看板」可看：被浏览、被转发、被电话联系总量 + **最近动态流水**（时间、类型、对象、脱敏访客标识）
- 平台端「数据总览」含电话联系总量

**小程序用户统计**：微信登录成功后自动写入/更新 `mp_user`（含 `last_login_time`），即使未设置昵称头像也会计入。平台端「用户管理」展示用户总数、今日新增、今日活跃、近 7 日活跃，并支持按昵称/OpenID 搜索；「数据总览」同步展示用户总数。历史浏览/询价/收藏记录中的真实 openid 会在升级时一次性回填。

**用户详情与备注**：用户列表「详情」抽屉展示头像昵称、openid、首次/最近登录，以及浏览、转发、电话、收藏、询价五项统计和对应的最近记录流水；平台可填写备注（≤200 字，V16 新增 `mp_user.remark`）用于标记重点客户。列表支持按当前筛选导出用户 CSV。

**平台询价管理**：平台端「询价管理」汇总全平台线索，顶部展示询价总数/待报价/已报价/今日新增，支持按关键词（联系方式/需求/OpenID）、商户名称、状态、提交日期筛选；行内展开可看报价详情，并可导出 CSV（含商品、商户电话、用户与报价信息）。

**商户经营画像**：商户列表「详情」抽屉展示账号状态、到期时间、入驻时间，产品/浏览/电话/询价/报价/跟进/转发八项指标，以及热门产品、最近询价与最近动态，方便运营快速判断商户活跃度。

**业务趋势**：平台端「数据总览」新增 7 / 30 天趋势图（纯 CSS 柱状图，无图表库），按日展示浏览、询价、新增用户；数据来自 `GET /api/admin/stat/trend?days=`。

**导航到店**：商户端「我的门店」填写经纬度（腾讯地图坐标拾取器获取），小程序商户主页/产品详情展示「到店导航」；未填坐标时自动降级为复制地址。

**询价闭环**：产品详情「聊价格」提交数量/期望到货/联系方式/需求说明 → `inquiry` 表 → 商户端「询价线索」报价（单价、总价、有效期、说明）→ 状态流转「待报价 → 已报价 → 跟进中」→ 小程序「我的询价」查看报价并可直接电话联系商户。商户可删除无效线索。

**询价提醒**：商户端左侧菜单「询价线索」显示待报价数量角标，每 30 秒轮询，数量增加时弹出通知；小程序在 tabBar「我的」显示红点，进入「我的询价」后自动清除。商户报价成功后，后端通过微信订阅消息通知询价用户（`WxSubscribeService`，access_token 内存缓存、40001/42001 自动刷新、43101 未授权静默跳过）；模板未配置时自动停用，不影响报价主流程。

**登录安全**：同一账号连续 5 次密码错误后锁定 10 分钟，成功登录后清零。限流记录保存在单机内存中，服务重启后清零。

**商品批量导入导出**：

- 平台端「产品管理 → 下载模板 / 导入商品」：CSV（UTF-8 BOM，Excel 可直接打开），必填列「商户手机号、商品名称、品类」，可选品牌/产地/规格/型号/价格/单位/图片/描述；单次最多 2000 行、5MB。
- 导入会校验商户手机号存在且已通过审核、品类唯一、字段长度与价格格式，并检查文件内及库内「同商户 + 同名称 + 同规格」重复；**任一行有错则整批不导入**，页面展示错误行号与原因。
- 「导出」按当前筛选条件导出商品清单；商户端「我的产品 → 导出商品」导出本商户商品。

**操作日志**：平台端「操作日志」记录商户审核、重置密码、产品审核的操作人、时间、内容与 IP，支持按类型、操作人、日期筛选（`operation_log` 表，V12）。

**收藏**：产品详情与商户主页可收藏/取消收藏 → `favorite` 表（同一访客对同一对象唯一）→ 「我的-我的收藏」按产品/商户分栏找回。

**微信登录**：小程序启动时调用 `wx.login()`，后端 `POST /api/mp/login` 用 `code` 调微信 `jscode2session` 换取真实 `openid` 并缓存；浏览记录、收藏、询价均绑定该 openid。旧版本生成的 `mp_` 假标识会在首次启动时自动清除。AppSecret 只放服务器配置，不进入小程序代码与仓库。

**用户昵称/头像**：小程序「我的」页使用微信的头像选择（`open-type="chooseAvatar"`）与昵称填写（`input type="nickname"`），头像经 `/api/mp/upload` 上传到 OSS，昵称与头像地址通过 `GET/POST /api/mp/profile` 按 openid 保存到 `mp_user` 表，换设备后仍可恢复。

**附近商户**：商户列表支持「综合热度 / 离我最近」切换。选择离我最近时小程序申请定位，后端按 Haversine 球面距离计算并由近到远排序，列表展示「距您 xxx」；未填写坐标的商户排在最后。接口为 `GET /api/mp/merchants?lat=&lng=&sort=distance`。

**市场公告**：平台端「内容管理 → 市场公告」发布，小程序首页顶部滚动展示（`notice` 表）。

**商户热度排序**：商户列表默认按「浏览 1 分 + 转发 2 分 + 电话 5 分」加权排序，活跃商户优先曝光；授权定位后可切换距离排序。

**配置缓存**：品类（含商品列表的品类名映射）、轮播、广告位、市场公告走进程内 Caffeine 缓存（`CacheConfig`，30 分钟过期兜底），平台端新增/修改/删除后立即清除；服务重启即清空。当前单机部署无需 Redis，后续多实例再换共享缓存。

**站内消息（在线咨询）**：

- 入口：tabBar「消息」看全部会话；产品详情、商户主页「在线咨询」直接进入与对应商户的会话。同一用户与同一商户唯一会话（`chat_conversation` 唯一索引 `openid + merchant_id`）。
- 消息类型：文字（≤500 字）、图片（走 `/api/mp/upload` 到 OSS，仅接受 `http(s)://` 或 `/upload/` 地址）、商品卡片（后端按 `productId` 生成快照，原文仅存 ID 与名称，商品改价不影响历史消息）。同一会话内同一商品只自动发一次，反复从详情进入复用已有卡片。
- 身份校验：`/api/mp/login` 除 `openid` 外下发聊天 token（JWT，`type=mp`，默认 720 小时），`/api/mp/chat/**` 与 `/ws/chat` 均校验该 token；query 里的 `openid` 只作一致性校验，与 token 不符返回 403。
- 实时推送：`/ws/chat`（`ChatSocketHandler` 鉴权：用户用 Bearer token 且 openid 必须在 `mp_user` 存在，商户用 JWT 且必须带 `merchantId`），消息仍走 REST 落库后由服务端推送，连接只负责接收；小程序端 8 秒增量轮询兜底，断线不影响收发。
- 已读与未读：打开会话调用 `/chat/read` 清零本方未读；tabBar「消息」显示未读角标（`wx.setTabBarBadge`），商户端商家中心「我的消息」显示未读汇总。
- 内容安全：用户发送的文字先过微信 `msg_sec_check`（scene=2、version=2）；接口异常时放行并记警告，不阻断沟通。会话可长按商户气泡举报，写入 `operation_log`（`chat_report`）。
- 商户回复时，若用户授权过订阅消息，推送「咨询回复通知」并直达对应会话；未授权只留未读角标。
